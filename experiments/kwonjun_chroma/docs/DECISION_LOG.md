# 주요 기술 의사결정

최종 갱신: 2026-10-20

| 결정 | 비교한 대안 | 선택 근거 |
|---|---|---|
| Ubuntu/WSL 중심 실행 | Windows 네이티브 통일 | CUDA·경로·패키지 재현성이 높고 Windows 사용자는 WSL로 참여 가능 |
| 부모–자식 청킹 | 고정 길이 단일 청킹 | 부모는 원문 문맥, 자식은 검색·군집 의미 순도를 담당 |
| 정책 전용 25,340개 청크 | 전체 438,708개만 사용 | 진행·인사·명단 잡음을 줄이고 전체 인덱스는 근거 검색 기준선으로 보존 |
| Arctic 임베딩 | KURE, BGE-M3, Dense RRF | 검수 dev에서 nDCG@5 0.9908, MRR 1.0으로 최고 |
| 단일 dense 검색 | BM25, RRF, reranker | 복합 구성의 nDCG·Recall 개선이 없어 복잡도만 증가 |
| FAISS + Chroma 역할 분리 | 한 저장소만 사용 | FAISS는 정확 기준선, Chroma는 영속 저장·메타데이터 필터·데모에 적합 |
| MiniBatchKMeans K=160 | K=100, 밀도 기반 군집 | K=100보다 중심 유사도가 높고 빈 군집 없이 세부 정책 단위 형성 |
| Qwen3 8B 로컬 | 외부 API, EXAONE, Gemma | 외부 전송 금지 준수, 한국어·구조화 출력·RTX 노트북 실행 균형 |
| LLM은 이슈명 제안만 | LLM 전체 분류 | 군집 재현성을 유지하고 환각이 관측일·전파 계산에 미치는 영향 제한 |
| 75% 군집 품질 게이트 | LLM coherent 판정 그대로 사용 | 대표 근거 지지율이 낮은 혼합 군집을 코드가 자동 거부 |
| Logistic/LightGBM + fallback | LLM 단독 예측 | 시간순 검증 수치와 실패 시 보수적 규칙을 제시 가능 |
| 실제 지도 + 번호형 마커 | 긴 텍스트 지도 라벨 | 지역·순서가 분리되어 겹침이 없고 hover로 상세 확인 가능 |
| 팀 저장소 별도 실험 폴더 | 팀 코드에 바로 병합 | 기존 `src/`, `scripts/`와 충돌 없이 리뷰·비교 후 통합 가능 |

## 검색기 채택 근거

```text
Arctic nDCG@5 0.9908 / Recall@5 0.2851 / MRR 1.0000
Dense RRF      0.9899 /          0.2851 /     1.0000
KURE           0.9813 /          0.2841 /     1.0000
Hybrid RRF     0.9684 /          0.2803 /     1.0000
Hybrid rerank  0.9642 /          0.2813 /     0.9896
BM25           0.8568 /          0.2675 /     0.9896
```

현재 라벨 규모에서는 Arctic 단일 검색이 가장 좋다. 다만 Recall@5가 낮아 보이는 이유는
한 질의에 관련 청크가 다수인데 평가 컷오프가 5이기 때문이다. 다음 실험에서는 Recall@20,
의회 다양성, 최초 관측 근거 적중률을 함께 본다.

## 변경 가능 조건

- 평가 질의가 늘어난 뒤 하이브리드 검색이 신뢰구간 내에서 명확히 우세하면 재검토한다.
- 정책 메타데이터 필터가 안정화되면 Chroma의 `where` 조건을 검색 UI에 추가한다.
- 예측 모델이 시간순 F1·balanced accuracy 기준을 통과하지 못하면 모델명을 내세우지 않고
  `trend_fallback`과 낮은 신뢰도를 표시한다.
