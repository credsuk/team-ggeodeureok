# 생성형 AI 및 외부 도구 활용 범위

## 사용 도구

| 도구·모델 | 사용 단계 | 적용 범위 |
|---|---|---|
| Ollama `qwen3:8b` | 검색 결과 설명·Agent | 로컬에서 검색 근거와 계산 결과를 자연어로 설명 |
| Ollama 로컬 LLM | 평가셋 보조 라벨 | 검색 후보 관련도 0·1·2 초안 생성 후 형식·샘플 검토 |
| `dragonkue/snowflake-arctic-embed-l-v2.0-ko` | 임베딩 | 자식 청크를 1,024차원 정규화 벡터로 변환 |
| `BAAI/bge-reranker-v2-m3` | 재순위 | 질의와 1차 후보를 함께 읽고 관련도 재평가 |

## 사용하지 않은 범위

- 회의록 원문을 OpenAI·Anthropic 등 상용 외부 LLM API에 전송하지 않았다.
- LLM이 최초 관측일, 전파 순서, 월별 건수, 예측 수치를 생성하지 않는다.
- 수치 예측은 제공된 2024~2025년 회의록에서 계산한 특징과 통계 모델이 담당한다.
- 공식 제출 모드에서는 기준일 이후 외부 자료를 분석·예측 입력으로 사용하지 않는다.

## 참가자의 판단과 검증

- Raw·Enriched 입력을 동일 평가셋에서 비교해 Raw를 선택했다.
- Arctic·KURE를 같은 질의·표본으로 비교해 Arctic을 선택했다.
- ChromaDB·pgvector를 같은 90만 벡터와 질의로 비교해 필터 검색이 빠른
  pgvector를 최종 DB로 선택했다.
- Dense 검색의 의미 유사도와 BM25의 정확 키워드 검색을 RRF로 결합하고,
  BGE 재순위로 상위 후보를 다시 검토한다.
- 이슈 군집은 유사도 그래프와 Union-Find로 계산하고 사람이 대표 근거를
  검수한 뒤 `issue_id`를 고정한다.
- 예측은 expanding-window rolling backtest로 미래 정보 누출을 방지한다.

## 검토한 대안과 실패 사례

- 파일 인코딩을 UTF-16으로 잘못 판정한 문제를 BOM·실제 디코딩 검사로 수정.
- 구 메타데이터와 수정 원본의 행 불일치 때문에 최신 원본에서 메타데이터를
  다시 생성하고 `row_id` 결합을 검증.
- Enriched 임베딩이 평균 검색지표를 개선하지 않아 Raw로 전환.
- ChromaDB는 단순 검색이 빠르지만 지역·연도 필터 검색이 느려 pgvector 채택.
- 로컬 LLM 배치 라벨에서 일부 ID가 누락되어 단건 판정 fallback과 재시도 적용.

## 외부 공공데이터

법제처·열린국회정보·KOSIS 연동 코드는 확장 기능으로 제공하지만 공식 제출
실행에서는 `COUNCIL_ENABLE_EXTERNAL_REFERENCE=0`이 기본이다. 명시적으로
활성화하더라도 외부 결과는 `reference_only`로 표시되며 회의록 기반 수치
예측의 학습 특징에는 포함되지 않는다.
