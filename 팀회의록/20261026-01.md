- **회의 일시:** 2026년 10월 26일(월)
- **주요 안건:** 주말 작업 진행상황 공유, 검색/DB 병목 분석, 모델 및 기준 정의, R&R(역할 분담) 및 향후 일정 수립

## 1. 진행 상황 공유 및 주요 이슈 점검

### 1) DB 및 조회 속도 (병목 현상)
- **속도 이슈:**
  - 전체 데이터 검색 시 LLM 및 DB 처리 시간이 과도하게 소요됨 (150초~3분 이상 소요, 간혹 타임아웃 발생).
  - 사전 캐싱/저장된 키워드(Top 5, 10개 군집 등)는 즉각 조회되나, 임의 키워드 검색 시 90만~100만 건 이상의 청크를 탐색하느라 지연 발생.
- **DB 현황 및 용량:**
  - Chroma vs PostgreSQL 비교 논의.
  - 전체 DB 덤프 용량이 약 7GB ~ 10GB(압축 전 25GB) 수준으로 대용량 적재/동기화 이슈 존재.
- **LLM 환경 점검:**
  - 로컬 LLM(Ollama 기반 Qwen 38B, Gemma 등) 구동 여부 확인.
  - 와이파이 연결 시에만 정상 동작하는 현상 발생 → 로컬 설정 및 외부 API 호출 여부 추가 점검 필요 (로컬 단독 구동 보장 필수).

### 2) 외부 데이터 연동 및 UI 시제품 (민지 님)
- HTML 기반 지도 확산 시각화, 향후 예측, 근거 데이터 매핑 프로토타입 구현.
- 외부 공공/통계 데이터(전세사기 건수 등 표 데이터) 연계 확인.
- 데이터 미조회 시 예외 처리 및 UI 크기 최적화(최대 8개 표기 후 더보기 방식) 개선 계획.

## 2. 프로젝트 핵심 기준 정의 (데이터/로직)

| 구분 | 논의 내용 | 결정 및 합의 사항 |
| :--- | :--- | :--- |
| **전파/확산의 정의** | 단순 키워드 출현 vs 동일 정책 맥락 전파 | 대회 주제("AI 기반 지역 이슈 트렌드 분석 및 정책 전파 확산 흐름 예측")에 맞춰 **키워드 기반 흐름 분석 + 유사도 검증** 방식으로 단순화하여 진행 |
| **유사도 기준치 (Threshold)** | 유사도 점수 컷오프 설정 | 초기 임계값 기준 **0.6 ~ 0.7 이상**으로 설정 후 테스트를 통해 최적 수치 조정 |
| **카운팅/집계 기준** | 일자별 다수 언급 건수 처리 | 기본적으로 **회의록 건수/발언 건수**를 기준으로 집계(대시보드 노출용), 유의미한 빈도 데이터 유지 |
| **행정구역 변경 대응** | 전라남도 등 행정구역 변경 이력 | 검색 시 과거/현재 행정구역 매핑이 가능하도록 고려 |

## 3. R&R (역할 분담)

- **제출 및 실행 환경 제약:** 별도 서버 설치 없이 로컬 제출 환경에서 바로 열람 가능하도록 **순수 HTML + JavaScript (Vanilla JS/jQuery)** 방식으로 UI 구성.

| 담당 영역 | 담당자 | 주요 업무 내용 |
| :--- | :--- | :--- |
| **모델링 & DB 최적화 (2명)** | **민지 님, 준 님** | - 각자 구축한 임베딩/청킹/DB 방식 성능 비교 후 단일 파이프라인으로 통합<br>- 유사도(0.6~0.7) 필터링 및 전파 흐름 로직 최적화<br>- 불용어(개회, 폐회 등) 전처리 통일 및 검색 속도 개선 |
| **백엔드 (FastAPI)** | **1명 (지원자)** | - 모델 추론 결과 및 DB 쿼리 연동 API 개발<br>- 프론트엔드 연동을 위한 엔드포인트 정의 및 Mock 데이터 선제공 |
| **프론트엔드** | **1명 (지원자)** | - 순수 HTML/JS 기반 반응형 대시보드 구현<br>- 지도 상의 정책 전파 애니메이션/화살표 효과, 발언 근거 툴팁 구현 |
| **테스트 스크립트 작성** | **1명** | - 모델 및 검색 로직 자동 성능 평가 스크립트 작성 |
| **발표 자료 (PPT)** | **1명** | - 전처리 과정, 모델 선정 근거, 임베딩 비교 데이터 정리<br>- 핵심 코드(2페이지 이상) 및 비교 장표 구성 (총 10장 내외) |

## 4. 향후 일정 및 마일스톤

- **화요일 오전:**
  - 각 파트별 1차 개별 구현 완료 (프론트는 Mock 데이터 기반 UI 작업, 백엔드는 API 엔드포인트 설계, 모델은 비교 테스트 완료).
- **화요일 오후:**
  - 모델 단일화 확정 및 프론트-백엔드-모델 API 통합/동기화 작업.
- **수요일:**
  - 최종 점검, 통합 테스트 및 PPT 최종 리허설/보완.
- **차기 회의:**
  - **화요일 오전 세션 종료 직후** 중간 싱크 회의 진행.
