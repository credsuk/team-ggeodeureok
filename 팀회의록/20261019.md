## 1. 회의 요약
회의록 데이터의 비정형성으로 인한 파싱 이슈와 로컬 LLM을 통한 메타데이터 추출 시 발생하는 속도 병목 문제를 공유하고 해결책을 논의했습니다. 프로토타입 시연을 통해 검색 후 LLM 정제 파이프라인의 유효성을 확인하였으며, 야간 분산 배치 작업 및 Git 브랜치 전략을 확정했습니다.

---

## 2. 주요 논의 및 결정 사항

### ① 데이터 전처리 및 회의록 식별 문제
* **현황 및 이슈:**
  * HTML 파일 내 회의 식별 키(구분자)가 누락되었거나 일관되지 않음.
  * 실제 회의 외에 '모두발언', '인사청문회', '감사' 등 성격이 다른 텍스트와 비언어적 표현(예: "고개를 끄덕임")이 혼재됨.
* **대응 방향:**
  * 정책 카테고리(대주제) 및 메타데이터 추출용 프롬프트 기준을 표준화하여 데이터 정합성 확보.

### ② 메타데이터 추출 성능 및 소요 시간 (병목 구간)
* **현황:**
  * 로컬 LLM(Ollama 등) 기반 메타데이터 추출 속도 지연 (16MB 파일 1개당 약 8~10시간, 행당 약 6.5초 응답 대기).
  * 2024년 강원도 데이터 파일 1건 처리에도 잔여 4시간 이상 소요 중.
* **대응 방안:**
  * 단일 환경 작업 대신 전 팀원 PC에 분담하여 퇴근 전 백그라운드 배치 작업 실행.
  * 멀티스레드(4스레드 등) 적극 활용.
  * 추후 필요 시 외부 API(GPT 등)의 병렬 배치 호출 방안 검토.

### ③ 임베딩, 검색 및 LLM 파이프라인
* **진행 경과:**
  * 2024~2025 전체 데이터 대상 텍스트 임베딩 작업 완료 (약 2~4시간 소요).
  * 1/10 샘플 데이터를 이용한 지도 기반 시각화 및 유사도 랭킹 대시보드 프로토타입 시연 완료.
* **파이프라인 구조 확정:**
  1. **1단계 (검색):** 임베딩 기반 유사도 검색 및 군집화(K-Means 등)로 관련 문맥 추출.
  2. **2단계 (정제):** 추출된 검색 결과를 LLM에 전달하여 최종 답변 생성 및 정리.

### ④ Git 브랜치 및 협업 규칙
* **작업 분리:** 개별 디렉토리 생성 대신 작업자/기능별 **Git 브랜치**를 따서 작업 진행.
* **브랜치 전략:**
  * `main`: 최종 제출 및 배포용.
  * `stage` / 개인 브랜치: 테스트 및 기능 개발용.
* **주의 사항:** 스크립트 및 데이터 파일명이 타 작업자와 충돌하지 않도록 명명 규칙 주의.
