## 🎯 2. 핵심 결정 사항 (Decisions Made)

### 1) 벡터 DB(Vector DB) 선정 및 벤치마크
* **Faiss 제외:** 메타데이터 필터링/저장이 원활하지 않아 최종 후보군에서 제외.
* **비교 대상:** **ChromaDB** vs **PostgreSQL (pgvector 등)**
  * 팀원 각자의 환경/선호에 따라 두 DB 중 하나를 선택해 파이프라인 구축 및 테스트 진행.
  * 최종 평가 기준: **검색 속도(Latency)** 및 **검색 정확도(관련도/유사도)**.
  * 진행 현황 및 DB 사용 내역은 공유 엑셀 시트에 각자 기록하여 현황 파악.

### 2) 메타데이터 추출 및 데이터 전처리 전략
* **이원화(2-Track) 전략 채택:**
  * **단기 (빠른 모델링용):** 파이썬 라이브러리를 활용해 상위 키워드/요약 중심의 메타데이터를 빠르게 일괄 추출하여 팀원들에게 우선 배포.
  * **장기 (품질 개선용):** LLM을 활용한 정밀 메타데이터 추출은 소요 시간이 매우 크므로, **야간/퇴근 시간**을 활용하여 백그라운드로 배치(이어하기 기능 활용) 작업 진행. 완성되는 대로 데이터를 고품질 데이터로 교체(갈아끼우기).
* **데이터 일관성 유지:** 성능 비교의 공정성을 위해 모든 팀원은 동일한 원본 데이터셋 + 추출된 메타데이터를 결합하여 임베딩 및 청킹을 수행.

### 3) 모델 파이프라인 구조
* **기본 흐름:**
  $$\text{사용자 쿼리} \xrightarrow{} \text{키워드 추출} \xrightarrow{} \text{DB 메타데이터/벡터 유사도 검색} \xrightarrow{} \text{Re-ranking(재순위화)} \xrightarrow{} \text{최종 JSON 아웃풋}$$
* **결과물 형식:** UI/프론트엔드 표출이 아닌, **지정된 JSON 포맷**에 맞춰 답변 및 근거 데이터가 반환되도록 구현. (세부 JSON 규격은 추후 공유 예정)

### 4) 개발 환경 및 가상환경 기준
* **환경 통일:** 엄격한 동일 버전 강제 대신 **각자 환경에서 자유롭게 구성**하되, 추후 통합/제출을 위해 `requirements.txt` 또는 가상환경 명세 파일 생성을 의무화.
* **파이썬 권장 버전:** Python `3.11.x` ~ `3.12.x` 대역 사용 중인 팀원 다수 확인.
