## 1. 아키텍처 및 기술적 의사결정 정리

### 1.1. 청킹(Chunking) 및 인덱싱 전략
- **부모-자식 청킹 (Parent-Child Chunking) 도입:**
  - **방식:** 작은 단위(자식 청크: 250~700자)로 검색 및 임베딩을 수행하여 정확한 핵심 키워드/의미를 매칭하고, 답변 생성 시에는 더 큰 컨텍스트(부모 청크: 2,400~3,200자)를 불러와 답변 완성도를 높임.
  - **효과:** 짧은 단어 검색의 정확성과 긴 문맥 이해도를 동시에 확보.

### 1.2. Vector DB 및 임베딩 모델 선정 근거
- **DB 선정:** **PostgreSQL + pgvector** (또는 ChromaDB 비교 언급)
  - 관계형 DB의 메타데이터 관리 편의성과 벡터 검색 확장성(`pgvector`)을 결합하여 원본 분석 데이터와의 연계성 확보.
- **선정 기준:** Hugging Face 벤치마크 및 검색 성능 평가 지표(Retrieval@K, MTEB 평균 지표 등) 기반으로 근거 마련.
  - *발표 팁:* 엑셀의 복잡한 원본 표를 전부 띄우기보다는 평균 수치와 선정된 모델의 강점 위주로 간략히 요약 전달.

### 1.3. 검색 및 재순위화 (하이브리드 검색 & 군집화)
- **하이브리드 검색:**
  - **Dense 검색:** 임베딩 기반 의미(Semantic) 검색.
  - **Sparse 검색 (BM25):** 키워드/단어 빈도 기반 일치 검색.
- **Reranking & 군집화 (Clustering):**
  - 두 검색 순위를 결합한 후, 코사인 유사도(Cosine Similarity, 임계값 약 0.72 기준)를 통해 연관성이 높은 문서군끼리 군집화(Clustering)하여 정책 이슈/흐름을 도출하고 노이즈를 필터링.

### 1.4. 로컬 LLM / 회귀 모델 / AI 에이전트 역할 명확화
- **향후 예측:** LLM이 아닌 통계/머신러닝 회귀 모델(포아송 회귀, 시계열 등) 기반으로 수행.
- **로컬 LLM & AI 에이전트:** 
  - 검색된 컨텍스트를 바탕으로 질문에 응답하고 질의응답을 통제(System Prompt 적용).
  - 에이전트는 사용자와 대화형 인터랙션을 담당.
- **발표 전략:** 회귀 평가 지표($F_1$, MAE, RMSE 등)에 대해 질의응답 방어가 어렵다면 발표 슬라이드에서는 복잡한 수치 설명을 최소화하고 "전망 및 판단 근거 도출" 정도로 간소화(Keep/보류).

## 2. 발표 PPT 구성 및 슬라이드 다이어트 합의

복잡하고 많은 슬라이드를 줄이고, 청중(평가위원)이 직관적으로 이해할 수 있는 **5단계 파이프라인**으로 압축합니다.

| 단계 | 주요 내용 | 화면/시각화 자료 |
| :--- | :--- | :--- |
| **1. 데이터 전처리** | 크롤링/수집 원본(JSON, 비정형 텍스트) $\rightarrow$ 정제 과정 | 전/후 원본 JSON/텍스트 비교 이미지 1장 |
| **2. 청킹 & 인덱싱** | 부모-자식 청킹 구조 및 pgvector 적재 | 부모-자식 매핑 다이어그램 |
| **3. 하이브리드 검색 & 군집화** | Dense(의미) + BM25(단어) $\rightarrow$ 코사인 유사도 기반 군집화 | 하이브리드 검색 흐름도 |
| **4. 분석·예측 & 로컬 LLM** | 회귀 기반 분석 + 로컬 LLM 응답 파이프라인 | 간략한 로직 다이어그램 (지표 세부 수치는 축소) |
| **5. 에이전트 및 최종 시각화** | 사용자 인터랙션 웹 UI 및 시각화 결과 | 완성 웹 대시보드(HTML/링크) 시연 |

> **제외/보류 결정:**
> - 팀원 6명이 각자 작성한 개별 아키텍처 모델 비교표는 정량적 비교 근거 부족으로 슬라이드에서 제외 (최종 보고서 서면 제출용으로만 활용).

## 3. 핵심 코드(3선) 발표 선정

선생님/평가자의 질문 포인트를 고려하여 발표에 포함할 핵심 코드는 다음 3가지로 압축:

1. **외부 데이터 수집 / API 연동 코드:** 정책/공공 데이터 연계 구현부.
2. **하이브리드 검색 (Dense + BM25) 로직:** 두 검색 방식을 결합하고 순위를 매기는 핵심 알고리즘.
3. **코사인 유사도 기반 군집화(Clustering) 로직:** 임계치($\ge 0.72$)를 이용해 유사 데이터를 묶어내는 핵심 함수.

*(참고: 프롬프트 엔지니어링이나 원본 전처리 단순 크롤링 코드는 슬라이드에서 제외하거나 부록으로 이동)*
