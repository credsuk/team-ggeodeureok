# [회의록] 프로젝트 개발 진행 및 UI/UX·데이터 모델 피드백 회의

---

## 1. 회의 개요
* **일시:** 2026년 10월 27일 (화)
* **참석자:** 팀 전원 (프론트엔드, 백엔드/데이터 가공, 모델링/데이터 분석 담당 등)
* **목적:** 
  * 화면 UI/UX 구성 점검 및 수정 사항 도출
  * 데이터·모델 예측 파이프라인 연동 상황 점검
  * 공공데이터/외부 API 활용 방식 협의
  * 최종 발표 시연 방식 및 향후 일정 조율

## 2. 화면별 UI/UX 피드백 및 수정 결정 사항

### A. 메인 대시보드 & 10대 키워드 (TOP 10)
1. **카테고리 순서 조정:**
   * '10대 키워드' 섹션을 화면 최상단(맨 앞)으로 재배치.
2. **불필요/모호한 지표 제거 및 간소화:**
   * '최초 발언지' 카테고리 삭제 (본문 근거와 중복되며 기준이 모호함).
   * '차기월 지속 확률(%)', '예상 언급량' 등 복잡한 예측 퍼센티지/지표 카드 및 예상 그래프는 제거.
     * *결정 사유:* 산출 기준이 명확하지 않고 사용자가 오해하거나 불필요한 질문을 유발할 수 있음. 예측 관련 내용은 하단 향후 예측 뷰/지도 등으로 대체.
3. **용어 및 범례 표기 보완:**
   * '관측의회 수(17곳 중 12곳)' 등 축약된 지표는 사용자가 한눈에 이해할 수 있도록 하단에 명확한 설명(범례) 추가.
4. **레이더 연동:**
   * TOP 10 키워드에서 '레이더 보기' 클릭 시 해당 키워드에 대한 상세 분석 화면으로 전환.

### B. 근거/원문 검색 페이지
1. **검색 건수 안내 및 페이징:**
   * 백엔드 부하 및 성능 고려로 현재 20개 노출 유지. (전체 로딩 페이징은 구현 복잡도로 인해 미적용)
   * "총 검색 결과 중 상위 20개 결과만 표시됩니다"와 같은 명확한 안내 문구/필터 UI 추가.
2. **개발자용 기술 용어 순화 및 정리:**
   * '초고속 시맨틱 검색' 등 과도한 기술 표기 문구 삭제.
   * `유사도` 수치(소수점 등)는 기술적 용어이므로 제거하거나 일반 사용자가 이해하기 쉬운 용어(예: **신뢰도**, **일치율 99%**)로 변환하여 표기.

### C. 지도 및 타임라인 상세 뷰 (모달/상세 정보)
1. **인터랙션 통합 (호버 & 클릭):**
   * **마우스 호버(Hover):** 간략한 요약 정보만 작게 툴팁 형태로 노출 (지도 시야 가림 방지).
   * **마우스 클릭(Click):** 하위 영역이 아코디언/모달 형태로 펼쳐지며 '앞뒤 전체 문맥' 상세 내용 노출.
   * 별도로 분리되어 있던 '한 줄 요약'과 '앞뒤 문맥' 뷰를 하나로 통합.
2. **향후 예측 문구 및 근거 표기:**
   * LLM 기반 요약 문장("앞으로 ~지역에서 논의가 집중될 것으로 예상됨")을 눈에 잘 띄도록 상단으로 올리고 영역 확대.
   * 복잡한 수치 그래프/점수는 하단으로 배치하거나 부수적 요소로 정리.
3. **지도 가시성 개선:**
   * 지도 내 지역 텍스트 크기 축소 및 배경색(그레이톤 등) 처리로 시각적 피로도 감소.
   * 데이터 포인트가 돋보이도록 스타일 조정 (외부 지도 연동 여부 및 대안 이미지 활용 가능성 검토).

## 3. 데이터 및 모델 연동 협의

1. **예측 모델 및 방법론:**
   * 분류(Classification)와 회귀(Regression) 모델을 결합한 방식으로 예측 수행 (LLM 단독 예측 아님).
2. **공공데이터 / 외부 API 처리:**
   * 외부 공공데이터(성비, 지역 통계 등)는 수치 점수를 복잡하게 나열하기보다 **'예측 모델의 참조 근거'**로 활용.
   * UI에는 복잡한 수치 대신 **출처 표기**("202X년 OO 통계자료 활용") 또는 근거 요약으로 간결하게 노출.
   * **외부 API 예외 처리:** API 장애나 인터넷 단절 시 전체 프로세스가 중단되지 않고 기본 예측은 유지되도록 Fallback 처리. 사용자 화면에는 시스템 에러 대신 출처 미표기 등 자연스러운 예외 처리 적용.
3. **데이터 공유 요청:**
   * 모델 학습/검증용 데이터셋(약 10GB 내외)을 **공유 드라이브**에 업로드.
   * GitHub 코드 공유 시 호환성 문제를 방지하기 위해 **Python 버전 및 필수 라이브러리(requirements/environment)** 정보 동봉 필수.

## 4. 챗봇 기능 현황
* 현재 로컬 자바스크립트 기반 프로토타입 상태 (기본 추천 질문 3개 리스트 및 간단 인터랙션 제공).
* 기능 확장은 배제하고, 추후 필요 시 UI 크기(시인성) 조정 정도만 검토.

## 5. 발표(PT) 및 시연 계획

1. **발표 전략:**
   * **시연 우선 진행:** 글보다 동작 화면을 먼저 보여준 뒤(약 3분), 아키텍처 및 핵심 코드로 설명 전환.
   * 속도가 빠른 핵심 10대 키워드 위주로 시연하고, 시간이 걸리는 검색/예측은 사전 캐싱 데이터 활용.
   * PPT에는 팀원들이 질문에 명확히 방어할 수 있는 핵심 기술(전처리 정규화/LLM 선택자 구분, 코사인 유사도 검색, 분류/회귀 예측 로직 등) 위주로 정리.
2. **향후 일정:**
   * **팀원 일정:** 다음 날 오후 일부 팀원 반차/외출 예정.
   * **수요일 오전:** PPT 초안 및 발표 준비 회의 진행, 파트별 역할/룰 확정.
   * **추가 사항:** 모델 설명용 핵심 정리글 및 PPT 초안은 공유 폴더에 상시 업데이트 후 피드백 반영.
