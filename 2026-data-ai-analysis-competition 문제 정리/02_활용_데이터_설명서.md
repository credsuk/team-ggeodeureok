# 2. 활용 데이터 (Data Specification & Data Engineering)

본 과제는 광역 지방의회 회의록 빅데이터를 바탕으로 지역별 선도 정책의 태동을 포착하고, 타 의회로의 전파·확산 경로를 추적 및 예측하는 것을 목표로 합니다. 이를 위해 주최 측이 제공한 1차 원천 데이터(Primary Data)의 정밀 전처리를 수행함과 동시에, 전파 예측의 논리적 타당성을 강화하기 위해 공공 검증용 외부 참조 데이터(Secondary Data)를 엄격한 데이터 누수(Data Leakage) 방지 원칙 하에 결합하여 활용하였습니다.

---

## 2.1 데이터 활용 및 규정 준수 원칙

1. **제공 데이터 범위 내 '최초 관측' 기준 엄수**
   - '최초 등장'은 현실 세계의 모든 기록이 아닌, **주최 측 제공 데이터셋 범위 내에서 최초로 탐지된 회의일자 및 발언**을 엄격한 기준으로 정의합니다.
2. **원문 근거 보존 및 100% 역추적성(Traceability) 확보**
   - 모든 분석 결과와 예측 결과는 판단 근거가 된 `회의록명(MINTS_NM)`, `회의일자(MTG_DE)`, `원문 발언 구간(Utterance)`을 완전히 역추적할 수 있도록 데이터 고유 식별자 체계를 구축하였습니다.
3. **시계열 데이터 누수(Data Leakage) 차단 (Backtest Mode)**
   - 정책 확산 및 다음 달 언급량 예측 시 주최 측이 지정한 **분석 기준일 이전의 데이터만 학습 및 추론에 사용**하며, 기준일 이후의 정보가 모델에 선반영되는 것을 원천 차단하였습니다.
4. **데이터 보안 및 비인가 외부 전송 배제**
   - 제공된 회의록 원본 및 발화자 개인정보는 외부 상용 LLM API(OpenAI, Anthropic 등)로 전송하지 않으며, 전처리·메타데이터 추출·임베딩·추론의 전 과정을 로컬 독립 환경(On-Premise)에서 수행하였습니다.

## 2.2 주최 측 제공 원천 데이터셋 (Primary Dataset)

### 2.2.1 데이터 개요
- **데이터 출처**: 국회도서관 국가학술정보 클라우드 (LOSI)
- **제공 형식**: UTF-8 기반 JSON 형식의 광역 지방의회 회의록 레코드 배열
- **대상 지자체 및 기간**: 경기도의회, 강원특별자치도의회, 충청남도의회, 충청북도의회 등 광역의회 회의록 (2024년 ~ 2025년 기준 34개 지역×연도 데이터셋)
- **원천 데이터 스키마 명세**:

| 필드명 | 데이터 타입 | 예시 | 설명 및 분석 활용 방안 |
|---|---|---|---|
| `RASMBLY_NM` | String | 경기도의회 | 회의가 열린 광역 지방의회 명칭 (전파 경로 및 지역 노드 식별자) |
| `MTGNM` | String | 보건복지위원회 | 본회의 또는 소관 상임위원회 명칭 (정책 도메인 분류 및 가중치 반영) |
| `MINTS_NM` | String | 보건복지위원회 회의록 제373회(1차) | 회의록 정식 명칭 (결과물 필수 인용 근거 필드) |
| `MTG_DE` | String (8자리) | `20240216` | 회의 개최 일자 (`YYYYMMDD` 포맷, 시계열 정렬 및 선후관계 산출 기준) |
| `MINTS_HTML` | String (HTML) | `<div id='anH'><p>...</div>` | 회의록 원문 HTML 마크업 (발언자, 안건, 발언 내용 추출 원천) |

### 2.2.2 원천 데이터의 기술적 특성 및 해결 과제
1. **의회별 비정형 HTML 마크업 상이성**: 각 지자체 의회마다 회의록을 표현하는 DOM 구조와 클래스/태그명이 달라 일괄 정규식 처리가 불가능함.
2. **장문 구어체 및 의례적 노이즈(Noise)**: 개회 선언, 의사일정 상정, 단순 인사말 등 정책적 실질이 없는 발언이 다수 혼재되어 검색 및 유사도 계산을 왜곡함.
3. **다화자 교차 토론 구조**: 한 안건에 대해 의원과 집행부(도지사, 국장 등)가 질의응답을 주고받으므로, 발언 단위의 문맥 보존과 화자 구분이 필수적임.

## 2.3 외부 참조 데이터셋 명세 (Secondary / Reference External Sources)

대회 규정에 따라 외부 자료의 **명칭, 출처, 수집 기준, 용도 및 적용 범위**를 아래와 같이 명시하며, 외부 자료는 공식 예측 입력이 아닌 **'지역 간 전파 타당성 검증 및 해석 보조(Reference-only)'** 목적으로만 활용됩니다.

| 외부 데이터명 | 수집 출처 (URL) | 수집 기준 / 버전 | 활용 용도 (Purpose) | 적용 범위 및 데이터 안전장치 |
|---|---|---|---|---|
| **국가법령정보 / 자치법규정보시스템 (ELIS)** | [elis.go.kr](https://www.elis.go.kr) | 지자체별 조례 제·개정 공포일자 데이터 (기준일 이전 한정) | 의회 회의록에서 논의된 선도 정책이 실제 타 지자체 조례 제정으로 제도화되었는지 후속 확산 검증 | - 회의록 원문 전송 없음 (추출된 정책 키워드만 질의)<br>- 예측 모델의 입력 피처에서 제외하고 사후 타당성 설명 근거로만 분리 제시 |
| **KOSIS 국가통계포털 (e-지방지표)** | [kosis.kr](https://kosis.kr) | 지자체별 통계지표 (고령화율, 재정자립도, 출생률 등) | 선도 의회의 정책이 타 지자체로 전파될 객관적 당위성(지역 현안 유사도) 분석 | - 사전 정의된 시도별 통계 테이블 ID만 참조<br>- 회의록 언급량 예측 보조 피처 및 리포트 배경 서술용 |
| **열린국회정보 (National Assembly Open Data)** | [open.assembly.go.kr](https://open.assembly.go.kr) | 국회 소관 상임위 의안 발의 데이터 | 지방의회의 지역 이슈가 중앙정부 및 국회 정책으로 상향 확산(Bottom-Up)되는지 연계 분석 | - 검증된 대표 정책 명칭만 참조<br>- 리포트 내 '국회 의정활동 지원' 항목의 연계 근거로 활용 |

> **외부 데이터 격리 원칙:** 대회 공식 평가의 공정성을 위해 외부 실시간 API를 활용한 결과는 기본 파이프라인에서 완전히 분리되며, 오프라인 사전 캐시 및 백테스트 모드를 기본값으로 동작하도록 구성하였습니다.

## 2.4 데이터 전처리 및 정제 파이프라인 (Data Preprocessing Pipeline)

원천 회의록의 잡음을 제거하고 검색 정밀도와 문맥 보존을 극대화하기 위해 5단계의 데이터 엔지니어링 과정을 구축하였습니다.

```mermaid
flowchart LR
    A["원천 회의록 JSON<br>(MINTS_HTML)"] --> B["적응형 파서 정제<br>(CSS/태그 노이즈 제거)"]
    B --> C["발화 단위 구조화<br>(화자/직함/안건 분리)"]
    C --> D["로컬 LLM 정책 태깅<br>(분야/이슈/요약 생성)"]
    D --> E["Canonical 데이터셋<br>(2,057,214행 구축)"]
    E --> F["부모-자식 계층형 청킹<br>(자식 901,358 청크)"]
```

### 1단계: 적응형 DOM 파싱 및 노이즈 제거
- 각 의회별 HTML 렌더링 규칙을 파악하여, 머리말/꼬리말/페이지 번호/UI 잔재를 제거하고 실제 회의 발언 본문만을 정밀 추출하였습니다.
- 단순 회의 진행 발언("이의가 없으므로 가결되었음을 선포합니다" 등) 및 의례적 인사를 정제 필터링하였습니다.

### 2단계: 발화 단위(Utterance) 구조화 및 메타데이터 분해
- 회의록 본문을 문단이 아닌 **'단일 발언자 1회의 실질 발언(Utterance)'** 단위로 분할하였습니다.
- 발언자 문자열에서 `speaker_role`(의장, 도지사, 위원장, 위원), `speaker_name`(성명), `speaker_type`(의원/공무원)을 정규 분해하여 메타데이터로 부여하였습니다.
- `MTG_DE` 일자를 `연도(Year)`, `월(Month)`, `일(Day)`로 분해하여 시계열 인덱싱을 부여하였습니다.

### 3단계: 로컬 LLM 기반 정책 메타데이터 증강
- 비인가 외부 전송을 막기 위해 **로컬 LLM(`qwen3:8b`)**을 활용하여 각 발언의 정책적 유효성을 판별하였습니다.
- `policy_category`(복지/환경/교통/산업 등), `core_issue`(핵심 쟁점), `keywords`(주요 정책 키워드), `summary`(발언 요약), `is_substantive`(실질 정책 논의 여부) 메타데이터를 추가 생성하여 검색 필터링 효율을 대폭 향상시켰습니다.

### 4단계: Canonical 표준 데이터셋 구축
- 산재된 모든 지자체 회의록을 단일 표준 스키마인 **Canonical 데이터셋(총 2,057,214건 발화)**으로 일원화하였습니다.
- 파일 재정렬이나 병합 시에도 인용 근거가 바뀌지 않도록 발화별 불변 식별자인 `chunk_id`와 본문 무결성 해시(`text_sha256`)를 부여하여 Parquet 형식으로 저장·관리합니다.

### 5단계: 계층형 부모-자식 청킹 (Parent-Child Chunking)
- **자식 청크 (검색용, Child Chunk - 총 901,358개)**: 의미가 서로 다른 정책이 한 벡터에 섞이지 않도록 단일 발언 또는 300~500자 단위로 조밀하게 분할하여 임베딩 및 시맨틱/키워드 검색(Dense + BM25)에 사용합니다.
- **부모 청크 (문맥 복원용, Parent Chunk)**: 검색된 자식 청크의 전후 발언 및 안건 전체 문맥(1,500~2,000자)을 보존하여, 서술형 분석 결과 작성 시 왜곡 없는 원문 구간을 인용할 수 있도록 하였습니다.

## 2.5 데이터 무결성 및 품질 검증 (Quality Assurance)

1. **시간적 선후관계의 정합성 검증**
   - 회의일자(`MTG_DE`)의 오름차순 정렬을 전수 검증하여 타임라인 왜곡 및 미래 데이터 참조를 원천 방지하였습니다.
2. **원문 일치율 100% 보장**
   - 모델이 인용하는 모든 원문 구간은 원천 JSON의 `MINTS_HTML` 텍스트와 100% 일치함을 SHA-256 해시 대조를 통해 자동 검증하였습니다.
3. **인과관계 단정 배제 검증 필터**
   - 보고서 생성 단계에서 'A 의회의 발의가 B 의회의 조례 제정을 직접 유발했다'와 같은 비약적 인과 단정을 차단하고, "선행 논의 관측 후 N개월 뒤 타 의회에서 후속 유사 논의가 관측됨(명시적 상호참조 여부 병기)"의 서술형 추정 양식을 엄수하도록 검증 파이프라인을 운영하였습니다.
