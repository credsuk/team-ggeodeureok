# model/ — 학습된 모델 파일

현재 `model/` 폴더에는 학습된 가중치 파일이 없습니다. 프로젝트는 임베딩·재순위화·LLM 모델을 별도로 fine-tune하지 않으며, 미리 학습된 모델을 추론 시 사용합니다.

## 현재 조정 가능한 검색 조합

이 설정은 신경망 내부 가중치를 학습하거나 바꾸는 기능이 아닙니다. 검색 결과의 상대 중요도를 정하는 값이며, 기본값은 기존 동작을 유지하는 `DENSE_RRF_WEIGHT=1.0`, `BM25_RRF_WEIGHT=1.0`입니다. `src/.env.example`을 참고해 개인 환경의 `src/.env`에서 조정할 수 있습니다. 예를 들어 dense 2, BM25 1은 벡터 검색 순위 기여를 키우는 실험값입니다. 두 값은 확률이 아니며, 둘 다 0으로 설정할 수 없습니다.

Cross-Encoder 재순위 모델은 기본적으로 기존 `RERANKER_MODEL` 한 개만 씁니다. 선택적으로 `RERANKER_MODELS=model-a,model-b`와 `RERANKER_WEIGHTS=2,1`을 설정하면 각 모델의 점수를 직접 평균하지 않고 각 모델 순위를 가중 RRF로 합칩니다. 0 가중치 모델은 로드·추론하지 않으며, 적어도 하나의 가중치는 양수여야 합니다. 여러 모델을 동시에 불러와야 하므로 필요한 모델 파일이 로컬 캐시에 있어야 하고, 메모리 사용량과 응답 시간이 늘 수 있습니다. 기본값은 빈 목록이라 새 환경에서는 기존 단일 모델 동작과 같습니다. 현재 개발 환경의 `src/.env`는 `BAAI/bge-reranker-v2-m3`와 `dragonkue/bge-reranker-v2-m3-ko`를 1:1로 설정했습니다. 두 번째 모델은 첫 번째 모델을 기반으로 한국어에 맞게 조정된 것이며, 이 프로젝트에서의 품질 우위는 아직 평가하지 않았습니다. 해당 체크포인트는 프로젝트 폴더가 아니라 Windows Hugging Face 캐시에 있습니다.

검색/재순위 가중치와 모델 목록·모델 가중치, 모델 ID, 검색 한도는 답변 캐시 식별자에 포함됩니다. 이 설정을 바꾸면 이전 설정에서 만든 답변을 새 설정의 결과로 재사용하지 않습니다. 검색 가중치나 재순위 모델 변경은 Chroma/BM25 인덱스를 다시 만들 필요가 없지만, 임베딩 모델을 바꾸는 경우에는 해당 임베딩으로 색인한 별도 Chroma 컬렉션이 필요합니다. 현재 옵션 앙상블은 Cross-Encoder 재순위 단계이며, 여러 임베딩 모델의 병렬 컬렉션 앙상블은 구현하지 않았습니다.

가중치가 좋아지는지는 고정된 사람 검토 평가 질문으로 비교해야 합니다. 현재 품질 평가 세트는 준비되어 있지 않으므로 특정 조합이 더 정확하다고 주장하지 않습니다.

## 제출 전에 할 일

- 대회가 실제 모델 파일 제출을 요구하는지 공식 제출 안내에서 확인하세요.
- 모델을 추가로 학습하지 않았다면 가중치 파일을 만들거나 “학습 모델”이라고 기재하지 마세요.
- 실행에 필요한 모델은 현재 환경에서 `dragonkue/snowflake-arctic-embed-l-v2.0-ko`, `BAAI/bge-reranker-v2-m3`, `dragonkue/bge-reranker-v2-m3-ko`, Ollama의 `huihui_ai/exaone3.5-abliterated`입니다. 새 Cross-Encoder 체크포인트는 Hugging Face revision `2aca5884ecac490192af9ebd86836d9073d826cd`로 Windows 사용자 캐시에 내려받았으며, 이 폴더에는 들어 있지 않습니다. 이들은 사전학습/파인튜닝된 외부 체크포인트이며, 프로젝트가 직접 fine-tune한 모델은 아닙니다.
- 대회 제출을 위해 별도 학습 모델을 만들 경우에만 해당 파일과 모델 카드(기반 모델, 학습 데이터·라이선스, 학습 설정, 평가 결과, 재현 방법)를 추가하세요. 용량·재배포 권한을 먼저 확인하세요.

가중치가 준비되지 않은 환경에서는 모델 다운로드가 기본적으로 차단되어 앱 추론이 실행되지 않을 수 있습니다. 실행 전 `src/.env.example`과 루트 README를 확인하세요.
