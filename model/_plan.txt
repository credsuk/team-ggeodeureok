의회 회의록 RAG 파이프라인
=========================

설정
- 각 메타데이터/회의록 쌍을 안정적으로 고유한 키와 함께 _constant.py의 DATASETS에 추가합니다.
- CHUNK_SIZE/CHUNK_OVERLAP은 문자 수 기준입니다. 초기 한국어 설정은 보수적으로 500/50을 사용합니다.

색인화
1. Chroma 문서 내용으로는 발언(utterance) 텍스트만 색인하고, 메타데이터는 row_id를 기준으로 결합합니다.
2. 컬렉션을 변경하기 전에 설정된 모든 파일을 사전 점검하고, 헤더·행 ID·날짜 및 의회 정보의 일치 여부를 검증합니다.
3. 의회나 연도 간 row_id 충돌을 방지하기 위해 모든 Chroma ID와 메타데이터에 데이터셋 키를 포함합니다.
4. 재색인 시 각 데이터셋의 기존 ID를 새 ID로 교체하며, 상향(upsert)이 성공한 뒤에만 더 이상 사용되지 않는 ID를 삭제합니다.
5. 모든 회의록 행에 대응하는 메타데이터가 있다고 전제합니다. 색인 전에 row_id 기준 전체 대응 여부를 검증하며, 누락·불일치가 있으면 건너뛰지 않고 컬렉션 변경 전에 오류로 중단합니다.


색인 입력 및 메타데이터
=====================
- 현재 설계는 색인에 사용할 회의록 텍스트와 메타데이터 파일이 이미 준비되어 있다고 전제합니다. 회의록 전처리 과정은 이 문서에 포함하지 않으며, 추후 별도 설계로 추가합니다.
- 벡터화 대상은 회의록 행의 발언 본문인 utterance입니다. utterance를 문자 기준 청크로 나누어 임베딩하며, 초기 설정은 CHUNK_SIZE=500, CHUNK_OVERLAP=50입니다.
- 각 청크에 임베딩과 함께 다음 메타데이터를 저장합니다.
  - 연결·색인 식별자: dataset_key, row_id, chunk_index
  - 회의·발언 정보: date, assembly, agenda_title, speaker_role, speaker_name, speaker_type
  - 분석 메타데이터: is_substantive, policy_category, core_issue, keywords, summary
- 입력 형식에 따라 회의·발언 정보의 원본 열 이름은 달라질 수 있습니다. 예를 들어 MTG_DE, RASMBLY_NM, MTGNM, MINTS_NM은 회의 날짜·의회·회의명 관련 열로 들어올 수 있으며, 색인 시 표준 메타데이터로 보존합니다.
- JSONL의 speaker와 agenda 값은 별도 중복 필드로 유지하지 않고, 회의록 열의 speaker_role/speaker_name 및 agenda_title 정보를 사용합니다. row_id는 JSONL과 회의록 행을 연결하는 키입니다.
- 발언 본문 utterance는 메타데이터로 저장하지 않고 벡터화할 문서 내용으로 사용합니다. 같은 행에서 만들어진 모든 청크는 원래 row_id와 회의 메타데이터를 유지합니다.

분석 및 출력
1. LLM은 질문에서 검색 주제·검색어·포함 표현과 사용자가 지정한 조건만 구조화하며, 사실이나 근거를 작성하지 않습니다.
2. 후보 검색은 주제 관련 메타데이터와 발언 본문을 대상으로 단어 기반 검색과 벡터 검색을 결합합니다. 검색 결과의 관련성은 Cross-Encoder로 검증하며, 통계는 검색 결과 범위의 참고 지표로만 사용합니다.
3. 통계 집계는 의회·날짜·주제 기준으로 중복 제거합니다. 같은 의회의 같은 날짜에 여러 안건이나 회의가 있어도 최대 1건으로 셉니다.
4. 근거는 색인된 정확한 원본 행에서 가져오며, 출력에는 요청된 다섯 가지 표 항목을 사용합니다.
5. 최초 관측은 검색 조건에 맞는 벡터 DB 자료 중 회의 날짜가 가장 빠른 기록입니다. 전망은 근거가 부족할 때 자료 부족과 낮은 신뢰도를 표시합니다.

한계
- 샘플 데이터셋만으로는 전국 단위의 포괄성이나 실제 최초 등장을 입증할 수 없습니다.
- 원본에 공식 회의 ID가 없는 경우 회의 순서는 원본 파일의 순서로 추정합니다.
- 사용 전에 구문 및 정적 검증을 실행합니다. 전체 Chroma 색인화와 로컬 모델 호출은 설정된 패키지와 모델이 필요하며, 의도적으로 별도 작업으로 수행합니다.

합의된 설계 기준
================
※ 이 절의 기준이 위 초기 구상 흐름과 다를 경우 이 절을 우선 적용합니다.

자료 범위와 시점
- 벡터 DB에 저장된 데이터만 사용하며 외부 조회는 하지 않습니다.
- 현재 분석 대상은 2024~2025년 자료와 특별시·광역시·도 단위 17개 의회입니다.
- 결과에는 분석 대상 기간과 데이터의 최종 날짜를 표시합니다. 데이터 최종 날짜 이후의 현재 동향으로 단정하지 않습니다.

질의 해석 및 주제어
- 사용자는 키워드뿐 아니라 자연어 문장으로 질문할 수 있습니다.
- 로컬 LLM은 질문에서 분석 주제, 검색 질의, 포함 표현, 사용자가 지정한 기간·의회 조건, 분석 의도를 구조화합니다. 질문에 없는 기간이나 조건을 임의로 만들지 않습니다.
- ‘지역 소멸’, ‘지방소멸’, ‘지방소멸대응기금’을 같은 분석 주제의 검색 후보 표현으로 취급합니다.
- LLM이 확장한 검색어는 후보 탐색에 사용하고, 검색 결과는 관련성 검증을 거칩니다. 벡터 검색 결과를 사실 판정이나 완전한 누락 방지로 간주하지 않습니다.
- 검색은 단어 기반 검색과 벡터 검색을 결합하고, 결과를 합친 뒤 Cross-Encoder로 관련성을 재정렬·검증합니다.

근거 검색 및 통계
- 재정렬된 청크를 원본 회의록 행과 연결하고, 필요한 문맥을 보강합니다. 화면의 발췌문은 원문과 출처 ID를 추적할 수 있어야 합니다.
- 통계는 보조 지표입니다. 전체 데이터의 정확한 총량으로 표현하지 않고, 관련성 검증을 통과한 검색 자료 기준의 참고값으로 표시합니다.
- 집계 단위는 의회 × 회의 날짜 × 주제이며, 같은 의회에서 같은 날 여러 차례 언급되거나 여러 회의가 있어도 최대 1건으로 계산합니다.
- 통계 지표는 ‘총 언급 횟수’ 대신 ‘검색된 관련 의회·일 수(참고)’처럼 검색 범위가 드러나는 이름을 사용합니다.

현황·최초 관측·전망
- 화면에서는 ‘확산’이라는 표현을 사용하지 않습니다. 의회별로 이후 어떤 주제가 논의됐는지 날짜순으로 보여주며, 시간 순서만으로 영향 관계를 암시하지 않습니다.
- 최초 관측은 검색 조건에 맞는 벡터 DB 자료 중 회의 날짜가 가장 빠른 기록입니다. ‘전국 최초’가 아닌 ‘저장 자료에서 최초 관측’으로 표기하고 원문 근거를 연결합니다.
- 전망 영역은 항상 반환합니다. 고정된 예측 기간을 두지 않고, 관측된 쟁점과 미해결 사안을 바탕으로 앞으로 논의될 가능성이 있는 의제를 정성적으로 제시합니다.
- 전망에는 근거 자료 ID와 신뢰도 상태를 포함합니다. 근거가 부족하면 구체적 예측을 억지로 만들지 않고 자료 부족과 낮은 신뢰도를 표시합니다. 근거 없는 확률·수치·특정 시점 예측은 생성하지 않습니다.

출력 검증
- JSON은 스키마로 필드·자료형을 검증합니다.
- 보조 통계의 표시 범위, 근거 ID의 실제 존재, 발췌문과 원문 일치 여부, 데이터 기간 표기를 검증합니다.
- 검색 후보나 예측 문장만으로 원문에 없는 사실을 추가하지 않습니다.
