의회 회의록 RAG 파이프라인
=========================

이 문서는 현재 구현 기준입니다. 분석 흐름과 별도의 데이터 수집·전처리 단계를 구분합니다.

설정과 분석 범위
----------------
- 입력 루트는 model/_constant.py의 METADATA_ROOT와 TRANSCRIPT_ROOT에서 설정합니다.
- 입력 파일은 같은 stem의 JSONL/TXT 쌍이어야 합니다. 사전 점검은 model/coverage_report.py를 사용합니다.
- 분석 필터는 2024~2025년 특별시·광역시·도 17개 의회입니다. 필터가 입력 데이터나 Chroma DB에 모든 자료가 존재함을 보장하지는 않습니다.
- 제출 전 `python model/coverage_report.py`를 실행합니다. 범위가 불완전하면 누락 연도·의회와 함께 종료 코드 2를 반환합니다.
- CHUNK_SIZE/CHUNK_OVERLAP은 토큰이 아닌 문자 단위이며 초기값은 500/50입니다.
- 색인기 model/0_make_chroma_db.py는 사용자 요청에 따라 변경하지 않았습니다.

색인 입력·메타데이터
--------------------
- Chroma 문서 내용은 발언(utterance) 청크이며, 연결 키는 dataset_key, row_id, chunk_index입니다.
- 회의 정보는 MTG_DE, RASMBLY_NM, MTGNM, MINTS_NM, agenda_title 원본 메타데이터에서 가져옵니다.
- 현재 입력 규약은 JSONL row_id와 TXT의 데이터 행 순서가 일치하는 것입니다.
- 현재 색인기는 모든 파일의 원자적 사전 검증을 보장하지 않습니다. 여러 파일 중 뒤에서 오류가 발생하면 앞선 페어는 DB에 반영될 수 있습니다. 재색인 전 DB 백업을 권고합니다.
- 빈 발언이나 메타데이터 미대응 행이 있으면 색인 로그와 입력 범위 리포트에서 따로 확인하십시오.

질의·검색
----------
- 로컬 LLM은 자연어를 topic, query, include_terms, 기간, 의회 조건으로 구조화합니다. 제공 자료를 외부 API로 전송하지 않습니다.
- 기간을 지정하지 않으면 2024~2025년을 적용하고, 사용자 지정 기간은 이 범위와 교집합으로 제한합니다.
- 검색은 Dense 벡터 후보와 Chroma 부분 문자열 후보의 혼합 방식입니다. 메인 호출은 질의 표현별 최대 100개를 요청한 뒤, 컬렉션이 cosine metric일 때 `1 - distance`로 유사도를 계산해 0.6 이상인 벡터 후보만 남깁니다. lexical 결과는 이 기준을 통과한 벡터 후보의 랭킹만 보강하며, 유사도 없는 lexical-only 결과는 제외합니다. 점수 필터는 Chroma 검색 응답 이후 적용되므로 검색 호출 자체의 top-k 비용은 줄이지 않습니다. 표현당 lexical 후보 스캔 상한은 5,000개입니다.
- 컬렉션 metadata가 cosine이 아니거나 없으면 cosine similarity로 해석하지 않으며, 0.6 필터를 통과하는 후보가 없습니다. 현재 컬렉션은 `hnsw:space=cosine`으로 확인했습니다.
- 최초 관측과 후속 논의는 별도 DB 전수 검색 없이, 재랭킹 상위 최대 50개 후보를 확장한 결과에서 파이썬으로 계산합니다. 이는 색인 DB 전체의 최초 기록을 보장하지 않습니다.
- Cross-Encoder 기본 모델은 BAAI/bge-reranker-v2-m3입니다. 0.6 기준은 벡터 cosine 유사도 기준이며, Cross-Encoder의 점수 기준은 별개입니다. 재랭커는 통과 후보를 최대 50개 반환하도록 설정되어 있습니다.
- 외부 웹 자료 또는 분석 기준일 이후 자료를 근거로 사용하지 않습니다.

근거·통계·결과
--------------
- 통과한 벡터 청크를 최대 50개까지 확장해 원본 발언 행 단위로 복원하며, 겹치는 청크 경계는 중복 제거합니다. 원문 복원에는 해당 행의 다른 청크도 문맥으로 포함될 수 있습니다.
- 출처에는 날짜, 의회, 회의록명(MINTS_NM), 안건명, 원문 발췌, dataset_key, row_id, chunk ID를 넣습니다.
- sourceId는 dataset_key:row_id로 구성합니다. 회의록명은 원본 메타데이터에 없으면 빈 문자열로 두며 생성하지 않습니다.
- 요약·전망 인용과 타임라인 출처는 실제 반환된 근거 ID인지 최종 검증합니다.
- 통계는 유사도 기준 통과 후 확장된 재랭킹 상위 최대 50개 결과 안의 참고값이며 전체 발언량이나 전체 의회 점유율이 아닙니다. 집계 단위는 의회×회의일입니다.
- 최초 관측은 이 최대 50개 후보 안에서 날짜가 가장 이른 기록입니다. 제공 데이터 전체의 최초나 전국 최초라고 주장하지 않습니다.
- 별도 의미 군집화는 적용하지 않습니다. 청크는 원본 행 단위로 합치고, 타임라인·통계는 의회×회의일 기준으로 대표 행을 정리합니다. 추가 군집화는 대표 선정으로 인한 날짜·의회 누락 여부를 평가셋에서 확인한 뒤 검토합니다.
- 시간상 후속 논의는 인과관계나 정책 전파의 증거가 아닙니다.
- 전망은 정성적이며 근거가 부족하면 insufficient_evidence/low로 반환합니다.

평가·재현
---------
- 단위 테스트: `python -m unittest discover -s model/tests -v`
- 구문 검사: `python -m compileall -q model`
- 입력 범위 리포트: `python model/coverage_report.py` (불완전이면 종료 코드 2)
- 한국어 평가 데이터는 model/evaluation/queries.csv에서 작성합니다. 한 행에 query_id, query, 사람이 검토한 relevant_source_ids, ranked_source_ids를 채우고 ID 구분자는 `|`로 합니다. model/evaluation_runner.py는 Precision@k, Recall@k, MRR, Hit@k를 계산해 JSON 보고서를 생성합니다.
- 라벨이 없거나 평가 수가 적으면 모델 변경이 성능 개선이라고 주장하지 않습니다. dense 단독, lexical 단독, 결합, 재랭커 적용 전후를 같은 질의로 비교합니다.
- 제출 문서에는 정확한 라이브러리 버전과 실행환경 정보를 기록합니다. 현재 설치 정보를 `python model/write_environment_lock.py --output model/environment.json`으로 수집하고, 모델 이름/revision, 용도, 실행 방식, 하드웨어, 분석 기준일은 별도로 기록합니다.
- 실제 실행 의존성은 chromadb, sentence-transformers, torch, langchain-text-splitters, openai SDK 및 로컬 Ollama 서버입니다. 현재 환경에서 일부 필수 패키지 미설치 시 전체 실행을 완료로 간주하지 않습니다.

제출 시 남은 검수
-----------------
- 회의록명·날짜·의회·안건·원문 발췌·출처 ID를 포함한 이슈별 분석 사례를 제출합니다.
- 범위 리포트에서 빠진 연도·의회가 있으면 원본 데이터를 확보하고 전처리/색인을 완료한 뒤 다시 확인합니다.
- 원본 공식 회의 ID가 없으면 발언 원본 행은 추적할 수 있어도 같은 날짜 회의 간 진행 순서를 추정하지 않습니다.
- 최초 관측·후속 논의·전망의 정확도는 사람이 검토한 대회 평가셋으로 별도 측정합니다.
