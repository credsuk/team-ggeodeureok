# 의정이슈레이더 최종 실행본

기준: `credsuk/team-ggeodeureok`의 `notebook-minimal` 브랜치. 실행 파일은 `council_issue_radar.ipynb`입니다.

## 적용한 수정

- 전망 카드에서 대표 이슈의 `multi_issue_forecast`를 우선 사용합니다.
- 포아송 예상 언급량, 최근 활동률 기반 지속 추정 확률, 증가/유지/감소 방향을 표시합니다.
- 자유검색 등 모델 출력이 없으면 최근 3개월 문서 수 평균 기준선을 표시합니다.
- 모델의 군집 청크 수와 월별 그래프·기준선의 중복 제거 문서 수를 구분합니다.
- 실제 HTML에 전망 제목을 연결하고, 기존 항목별 후속 흐름 보고서는 유지합니다.
- A.X-4.0-Light 모델·240초 타임아웃을 기본값으로 맞췄습니다. 기존 `.env` 값이 우선합니다.
- 저장소 루트 또는 노트북 폴더에서 실행할 수 있도록 경로 인식을 보완했습니다.

## 실행

기존 PostgreSQL/pgvector 데이터베이스, Arctic 임베딩 모델 캐시, Ollama와 설명 모델이 필요합니다. 이 묶음은 회의록 데이터·모델 가중치·DB 덤프를 포함하지 않습니다.

1. 압축 해제 후 `notebook_minimal` 폴더에서 기존 Python 가상환경을 활성화합니다.
2. `pip install -r requirements.txt`를 실행합니다.
3. 기존 `.env`가 있으면 그대로 사용합니다. 없으면 `.env.example`을 `.env`로 복사하고 DB 접속정보를 입력합니다. 키와 비밀번호는 Git에 올리지 않습니다.
4. 선택한 로컬 Ollama 모델이 설치되어 있는지 확인합니다.
5. Jupyter 또는 VS Code에서 `council_issue_radar.ipynb`를 열어 커널을 재시작한 뒤 위에서 아래로 실행합니다. 마지막 서버 종료 셀은 실행하지 않습니다.
6. 기본 대시보드 주소는 `http://127.0.0.1:8000`입니다. 고정 이슈를 선택해 예상 청크 수·지속 추정 확률·방향과 항목별 전망을 확인합니다. 자유검색에서는 문서 기준선이 표시됩니다.
7. 이전 서버가 떠 있으면 종료하고 다시 실행한 뒤 브라우저를 강력 새로고침합니다.

## 검증 범위

JavaScript 구문과 노트북 전체 코드 셀의 Python 구문을 검사했습니다. 실제 HTML의 표시 대상과 합성 API 응답을 사용해 모델 우선 표시, 0건·확률 0, 자유검색 기준선 전환, null·잘못된 확률·빈 응답 처리를 확인했습니다.

이 환경에는 실제 회의록 DB·GPU·Ollama가 없어 종단간 실행과 실측 성능 재평가는 수행하지 않았습니다. `EXPERIMENT_AND_EVALUATION.md`의 예측 성능은 원본 Rolling Backtest 기록이며 이번 화면 수정의 재측정 결과가 아닙니다. 최소 실행본 검색은 PostgreSQL Dense·전문검색·RRF로 구성되며 원본 BM25·BGE reranker 실험과 구분합니다.

노트북에 저장된 과거 실행 출력은 제거했습니다. 화면 결과는 현재 환경에서 다시 실행해 생성합니다.
