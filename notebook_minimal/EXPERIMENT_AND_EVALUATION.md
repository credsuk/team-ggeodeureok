# 의정이슈레이더 실험 및 평가

## 1. 평가 목적

본 실험은 광역지방의회 회의록에서 사용자의 정책 질의와 관련된 근거를 정확히 검색하고, 동일 이슈의 논의를 하나로 묶어 최초 관측 시점과 지방의회별 후속 논의 흐름을 구성하며, 다음 달의 논의 지속 여부와 언급량을 예측할 수 있는지를 검증하기 위해 수행하였다.

평가는 다음 네 영역으로 구분하였다.

1. 임베딩 입력 형식 및 임베딩 모델 비교
2. 벡터 데이터베이스 검색 성능 비교
3. 검색·재순위·군집화 결과의 정합성 검증
4. 시계열 예측 성능 평가

모든 회의록 원문과 질의 처리는 로컬 환경에서 수행하였다. 제공 데이터는 외부 상용 LLM API로 전송하지 않았다.

## 3. 데이터 분할 및 평가 원칙

### 3.1 검색 평가

검색 실험에서는 같은 질의와 같은 후보 문서 집합을 사용하여 비교 대상만 변경하였다. 관련성은 다음 3단계로 판정하였다.

| 라벨 | 의미 |
|---:|---|
| 2 | 질의의 정책 대상·수단·문제와 직접 관련된 핵심 근거 |
| 1 | 배경, 유사 정책 또는 간접 관련 근거 |
| 0 | 질의와 무관하거나 절차적 발언에 가까운 문서 |

초기 관련성 후보는 로컬 LLM으로 자동 판정하고, 결과 형식 오류와 누락을 재시도·개별 판정으로 보완하였다. 최종 비교에서는 동일한 판정 집합을 모든 모델에 적용하여 모델별 평가 조건을 통일하였다.

### 3.2 예측 평가

예측 데이터는 대표 이슈 10개의 월별 패널로 구성하였다. 미래 정보를 학습에 섞지 않기 위해 무작위 분할 대신 시간순 Rolling Backtest를 사용하였다. 각 fold에서 과거 월만 학습하고 바로 다음 월을 예측하였다.

- 대표 이슈: 10개
- 학습 가능 월별 행: 180개
- 검증 예측: 100개
- Rolling fold: 10개
- 분석 기준일 이후 데이터: 미사용

## 4. 임베딩 입력 형식 비교: Raw vs Enriched

`raw`는 정제된 원문 중심 텍스트이고, `enriched`는 원문 앞에 안건·정책분야·핵심 이슈·키워드·요약 등 메타데이터를 결합한 텍스트이다. 메타데이터를 추가하면 항상 좋아질 것이라고 가정하지 않고 실제 검색 성능으로 비교하였다.

| 입력 형식 | nDCG@10 | Precision@10 | Recall@20 | MRR |
|---|---:|---:|---:|---:|
| Raw | **0.8928** | **0.9750** | **0.5826** | **1.0000** |
| Enriched | 0.8871 | 0.9667 | 0.5744 | 0.9896 |

- nDCG@10 차이(`enriched - raw`): -0.0057
- 95% bootstrap 신뢰구간: [-0.0224, 0.0110]
- 질의별 우세: Raw 18개, Enriched 21개, 동률 9개

신뢰구간이 0을 포함하므로 두 입력 방식의 차이가 통계적으로 명확하다고 보기 어려웠다. 다만 Raw가 전체 지표에서 소폭 높았고, LLM이 생성한 메타데이터 표현이 원문의 의미를 과도하게 일반화하거나 검색 벡터에 잡음을 추가할 가능성이 있었다. 따라서 최종 전체 임베딩에는 **Raw 입력 형식**을 채택하였다.

메타데이터를 폐기한 것은 아니다. 메타데이터는 임베딩 본문에 직접 결합하지 않고 지역·연도·위원회 필터, 결과 설명, 이슈명 보조 및 화면 표시에 사용하였다.

## 5. 임베딩 모델 비교: Arctic vs KURE

정책 회의록 검색에 적합한 한국어 임베딩 모델을 선택하기 위해 동일 평가 질의와 동일 관련성 라벨을 사용해 Arctic과 KURE를 비교하였다.

| 모델 | nDCG@10 | Precision@10 | 직접 관련 Precision@10 | MRR | 문서 임베딩 처리율 |
|---|---:|---:|---:|---:|---:|
| Arctic Ko | **0.8969** | **0.9833** | **0.8083** | 1.0000 | **58.95행/초** |
| KURE | 0.8657 | 0.9750 | 0.7833 | 1.0000 | 56.25행/초 |

- KURE-Arctic nDCG@10 차이: -0.0312
- 95% bootstrap 신뢰구간: [-0.0684, 0.0017]

두 모델의 MRR은 같았고 nDCG 차이의 신뢰구간은 0을 포함하였다. 그러나 Arctic이 nDCG@10, Precision@10, 직접 관련 Precision@10과 처리 속도에서 모두 더 높은 점 추정치를 보였다. 이에 최종 임베딩 모델로 `dragonkue/snowflake-arctic-embed-l-v2.0-ko`를 선정하였다.

최종 전체 임베딩 결과는 다음과 같다.

| 항목 | 결과 |
|---|---:|
| 임베딩 행 수 | 901,358 |
| 차원 | 1,024 |
| 소요 시간 | 4.14시간 |
| 처리율 | 60.49행/초 |
| 저장 dtype | float16 |
| 정규화 | L2 normalized |

## 6. 벡터 데이터베이스 비교: ChromaDB vs pgvector

동일한 901,358개 벡터, 동일한 10개 질의, `Top-K=10` 조건에서 ChromaDB와 PostgreSQL+pgvector를 비교하였다. Recall은 정확 검색 결과를 기준으로 계산하였다.

### 6.1 필터 없는 검색

| DB | p50 지연시간 | p95 지연시간 | Recall@10 | Top-1 일치율 |
|---|---:|---:|---:|---:|
| ChromaDB | **1.42 ms** | **2.14 ms** | 0.8700 | 0.8000 |
| pgvector | 2.75 ms | 4.31 ms | **0.9500** | **1.0000** |

### 6.2 지역·연도 필터 검색

| DB | p50 지연시간 | p95 지연시간 | Recall@10 | Top-1 일치율 |
|---|---:|---:|---:|---:|
| ChromaDB | 586.29 ms | 861.08 ms | 1.0000 | 0.9000 |
| pgvector | **3.97 ms** | **8.18 ms** | 1.0000 | 0.9000 |

필터가 없는 검색에서는 ChromaDB의 지연시간이 짧았지만 pgvector의 Recall과 Top-1 일치율이 더 높았다. 특히 실제 서비스에서 중요한 지역·연도 필터 검색에서 pgvector가 약 148배 빠른 p50 지연시간을 보였다. 따라서 최종 운영 DB로 **pgvector**를 선택하고 ChromaDB는 비교 기준선으로 보존하였다.

## 7. 검색 및 재순위 평가

최종 검색은 다음 단계를 사용한다.

1. Arctic Dense 검색으로 의미가 유사한 후보 검색
2. BM25로 정책명·사업명·법령명 등 정확한 단어가 일치하는 후보 검색
3. RRF(Reciprocal Rank Fusion)로 두 순위를 결합
4. BGE reranker로 질의와 후보 원문을 함께 읽어 최종 순위 재조정
5. 동일 본문 및 동일 부모 청크 중복 제거
6. 부모 청크를 연결하여 최종 근거 문맥 복원

Dense 검색은 표현이 달라도 의미가 비슷한 발언을 찾는 데 유리하고, BM25는 고유 정책명과 숫자·사업명 검색에 유리하다. RRF는 서로 다른 점수 체계를 직접 합산하지 않고 각 검색 결과의 순위를 이용해 안정적으로 결합한다.

자유검색 회귀시험에서 `자전거 안전정책` 질의는 다음 결과를 생성하였다.

| 항목 | 결과 |
|---|---|
| 분석 형태 | dynamic |
| 상태 | provisional_until_review |
| 최초 관측 | 2024-01-24 |
| 관측 의회 | 11개 |
| 원문 근거 | 14개 |
| 검색 방식 | dense_bm25_rrf_rerank_validated_cluster |

자유검색 결과는 자동 생성 결과이므로 검수 전에는 `provisional` 상태로 표시하고, 대표 이슈 결과와 구분하였다.

## 8. 이슈 군집화 및 전파 분석 검증

검색 상위 문서만 그대로 나열하면 하나의 넓은 질의 안에 서로 다른 세부 정책이 섞이거나 같은 회의의 인접 청크가 반복될 수 있다. 이를 해결하기 위해 후보 임베딩 간 유사도를 기준으로 연결 그래프를 만들고 Union-Find로 연결 성분을 병합하여 이슈 군집을 생성하였다.

군집화 과정은 다음과 같다.

1. 검색 및 재순위 후보 수집
2. 최소 관련도 기준 미달 후보 제거
3. 동일 부모 청크 중복 제거
4. 후보 간 코사인 유사도 계산
5. 임계값 이상인 문서를 같은 연결 성분으로 병합
6. 질의 seed 포함률, 관련도, 지역 다양성 및 시간 범위로 대표 군집 선택
7. 검수 후 `issue_id` 고정

과병합은 서로 다른 세부 정책이 하나의 군집으로 합쳐지는 현상이고, 과분리는 같은 이슈가 여러 군집으로 갈라지는 현상이다. 이를 줄이기 위해 임계값 sweep, seed 포함률, 동일 부모 중복 제거, 의회 다양성 및 대표 원문 검수를 함께 사용하였다.

저출생 대응 정책의 초기 검증 사례에서는 검색 후보 500개 중 358개가 기준을 통과했고, 94개 군집 중 seed 10개를 모두 포함한 대표 군집 158개를 선택하였다. 해당 결과는 8개 의회와 2024-01-25~2025-12-10의 기간을 포함하였다. 이후 검수된 대표 이슈는 고정 `issue_id`를 부여해 타임라인과 예측의 기준으로 사용하였다.

최초 관측은 **제공 데이터 범위에서 해당 이슈가 처음 확인된 회의일**을 의미한다. 지역 간 화살표는 인과관계를 입증하는 전파 경로가 아니라, 검수된 관련 회의록의 최초 관측 순서를 시각화한 것이다.

## 9. 예측 모델 및 평가

### 9.1 예측 과제

예측은 성격이 다른 두 문제로 분리하였다.

| 과제 | 출력 | 최종 모델 |
|---|---|---|
| 논의 지속 여부 | 다음 달 논의 있음/없음 | 최근 활동률 기준선 |
| 다음 달 언급량 | 0 이상의 이슈 의미 군집 member 청크 수 | 포아송 회귀 |

최근 활동률 기준선은 최근 몇 개월 중 해당 이슈가 실제로 논의된 비율을 이용하는 분류 기준선이다. 데이터가 대표 이슈 10개와 짧은 월별 기간으로 제한되어 복잡한 분류 모델보다 과적합 위험이 낮고, 시간순 검증에서 가장 높은 F1을 보여 최종 선택하였다.

언급량의 단위는 이슈 의미 군집의 member 청크 수이며 중복 제거 회의록 문서 수와 구분한다. 음수가 될 수 없는 건수형 데이터이므로 포아송 회귀를 사용하였다. 포아송 회귀는 평균이 커질수록 변동성도 커지는 카운트 데이터의 특성을 반영하고 예측값이 음수가 되는 문제를 피할 수 있다.

초기 단일 이슈 프로토타입에서는 최근 3개월 가중평균이 가장 낮은 오차를 보여 기준선으로 사용했다. 그러나 최종 제출 모델은 10개 이슈를 하나의 패널로 학습하고 시간순 Rolling Backtest로 비교한 결과에 따라 **포아송 회귀**를 선택하였다. 따라서 단일 이슈 실험 결과와 최종 다중 이슈 모델을 구분해야 한다.

### 9.2 평가 지표

| 지표 | 사용 이유 |
|---|---|
| F1-score | 논의가 있는 달이 적을 수 있으므로 Precision과 Recall을 함께 평가 |
| MAE | 예상 언급량이 실제값과 평균적으로 몇 건 차이 나는지 직관적으로 표현 |
| RMSE | 큰 예측 오차에 더 큰 패널티를 부여해 급증·급감 실패를 확인 |
| 방향성 정확도 | 전월 대비 증가·유지·감소 방향을 맞췄는지 평가 |
| Rolling Backtest | 미래 데이터 누수를 방지하고 실제 운영 순서를 모사 |

### 9.3 최종 결과

| 항목 | 결과 |
|---|---:|
| 논의 지속 여부 F1 | **0.8814** |
| 언급량 MAE | **7.1224건** |
| 언급량 RMSE | **10.0425건** |
| 방향성 정확도 | **0.7600** |
| Rolling folds | 10 |

단순 전월 유지 예측과 비교한 개선 결과는 다음과 같다.

| 비교 항목 | 개선 결과 |
|---|---:|
| 분류 F1 증가 | +0.0621 |
| MAE 개선율 | 29.83% |
| RMSE 개선율 | 24.31% |
| 방향성 정확도 증가 | +0.74 |

MAE 7.12건은 예측값과 실제 언급량의 절대 차이가 월별로 평균 약 7.12건이라는 의미이다. 이 값만으로 좋고 나쁨을 단정하지 않고 전월 유지 기준선 대비 29.83% 개선되었다는 상대 성능과 함께 제시하였다.

## 10. 로컬 LLM 비교 및 근거성 검증

### 10.1 실험 목적과 조건

로컬 LLM은 검색·집계·예측 결과를 근거 기반 문장으로 설명하는 역할을 수행한다. 비교 대상은 `main.py`의 `/api/chat` 답변 생성 단계이며, 검색 모델이나 시계열 예측 모델의 성능과 구분하여 평가하였다.

첨부 `report.md`에 기록된 2026-11-02 비교 실험은 RTX 4060 Laptop 8GB에서 Ollama 기본 옵션으로 수행하였다. 대표 이슈 질문 7개와 존재하지 않는 ‘화성 이주민 조례’ 질문 1개, 총 8개 질문을 사용했고 각 질문에 검색 근거 6건을 제공하였다. 모든 모델은 동일한 `evidence_top6.json`의 근거를 받았다.

이 비교에서는 **Dense(HNSW) 검색만 사용**하였다. 비교 당시 PostgreSQL 전문검색 절에 tsvector GIN 인덱스가 없어 약 90만 행을 순차 스캔했고 질문당 수 분이 소요되었기 때문이다. 따라서 아래 응답시간은 보고서의 답변 생성 단계 비교값이며 전체 하이브리드 검색·재순위 파이프라인의 종단간 지연시간으로 해석하지 않는다.

### 11.1 최종 실행 진입점

- 저장소: https://github.com/credsuk/team-ggeodeureok
- 브랜치: `notebook-minimal` (하이픈). 실행 폴더명은 `notebook_minimal` (밑줄)이다.
- 실행 노트북: `notebook_minimal/council_issue_radar.ipynb`
- 실행 전 `notebook_minimal/requirements.txt`를 설치하고 `.env.example`을 `.env`로 복사하여 기존 PostgreSQL/pgvector 접속정보와 로컬 모델 설정을 입력한다.
- 노트북을 위에서 아래로 실행하면 설정·DB 검증·검색·군집 및 예측·설명·FastAPI 대시보드 순서로 연결된다. 데이터베이스와 모델 파일은 별도로 준비해야 한다.

### 11.2 실험 파이프라인과 최소 실행본의 범위

앞 절의 하이브리드 검색 실험은 Dense + SQLite FTS5 BM25 + RRF + BGE reranker 구성의 기록이다. 최소 실행 노트북은 PostgreSQL Dense + 전문검색 + RRF를 사용하며 BGE 재순위 단계를 포함하지 않는다. 동일 검색 파이프라인이라고 간주하거나 앞 절의 검색 성능을 노트북의 재측정값으로 표시하지 않는다.

노트북은 원본 시간순 검증에서 선정한 최근 활동률 기준선과 포아송 회귀를 사용해 모델을 다시 학습하지만, Rolling Backtest 성능을 다시 측정하지 않는다. 9절의 F1·MAE·RMSE·방향성 정확도는 원본 `src/results/forecast_metrics.json`에 기록된 실험값이다. 입력 데이터·군집 구성·환경이 달라지면 예측 결과와 성능은 다시 검증해야 한다.

### 11.3 웹 예측·전망 표시 연결 보완

코드 점검에서 API가 반환하는 `multi_issue_forecast`를 전망 카드가 읽지 않고 `forecast`의 평균 기준선만 표시하는 연결 누락을 확인하였다. 대표 이슈는 포아송 예상 언급량·논의 지속 추정 확률·증가/유지/감소 방향을 우선 표시하도록 수정하였다. 자유검색 등 모델 결과가 없는 경우에는 문서 수 평균 기준선을 표시하며, 예측값 0건도 유효한 값으로 처리한다.

포아송 모델 출력은 **이슈 군집 청크 수**, 평균 기준선과 월별 막대그래프는 **중복 제거 문서 수**이다. 두 단위는 직접 비교하지 않으며 화면에서도 구분한다. API의 `followup_report`를 표시하는 항목별 전망 영역은 유지한다.

이 보완은 출력 연결 수정이며 예측 성능 향상을 뜻하지 않는다. 이번 수정의 정적 검사·합성 응답 기반 표시 검사는 별도 검증 기록에 남기며, 실제 DB·GPU·Ollama 환경의 종단간 실행 검증과 구분한다.

## 12. 한계 및 해석 시 주의사항

1. 최초 관측은 제공된 2024~2025년 회의록 범위 안에서의 최초 관측이며 정책의 실제 최초 발생을 의미하지 않는다.
2. 지역 간 전파선은 시간순 후속 논의를 나타내며 정책의 직접적인 인과 전파를 입증하지 않는다.
3. 자유검색 군집과 예측은 자동 생성된 임시 결과이므로 대표 이슈로 확정하기 전 사람의 근거 검수가 필요하다.
4. 예측 데이터가 대표 이슈 10개와 제한된 월별 구간으로 구성되어 장기 예측이나 구조적 정책 변화에는 불확실성이 크다.
5. F1과 MAE는 현재 데이터·라벨·평가 질의에 대한 값이며 다른 기간이나 새로운 지방의회 데이터에서 재평가해야 한다.
6. 외부 공공데이터는 회의록 결과의 보조 설명에만 사용하며 분석 기준일 이후 정보를 예측 입력에 사용하지 않는다.

## 13. 최종 선정 구성

| 단계 | 최종 선택 | 선택 근거 |
|---|---|---|
| 임베딩 입력 | Raw | Enriched 대비 전체 지표 소폭 우세, 생성 메타데이터 잡음 방지 |

| 검색 결합 | RRF | Dense와 BM25의 서로 다른 점수 체계를 순위 기반으로 결합 |
